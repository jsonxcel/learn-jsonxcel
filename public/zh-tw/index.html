為什麼選擇 JsonXcel

讓報表版式與應用程式碼解耦，同時保持 API 足夠簡單。

JSON 遇上 Excel 範本

設計師維護活頁簿，服務只傳送結構化 JSON；用標記繫結欄位，無需在程式碼裡畫表。

五語系範本目錄

同一個 template_name 位於 en-US / zh-CN / zh-TW / ja-JP / ko-KR。每次轉換傳入 language。

一個 convert 介面

POST /api/convert，攜帶 template_name、language、output_format 與 ds* 資料來源，回傳 Excel 或 PDF。

真實業務單據

訂單、報銷、預算、出貨單 — 保留設計師已使用的公式、樣式與圖表。

可上線營運

架構一覽

業務系統保持 JSON 原生；JsonXcel 負責範本解析與轉譯。

  1. 1

    準備 Excel 範本

    在活頁簿中放置標記與版式，存入 Templates/{language}/。

  2. 2

    產出業務 JSON

    ERP／SaaS／指令碼產生 ds、ds01 等負載 — 應用程式碼不再寫儲存格座標。

  3. 3

    呼叫 /api/convert

    JsonXcel 載入對應語系範本，繫結資料來源並執行 ProcessTemplate。

  4. 4

    取得 Excel 或 PDF

    將檔案串流回傳給使用者，或保存名稱／大小／路徑等中繼資料。

幾分鐘完成接入

一次 fetch 即可從 JSON 產生在地化活頁簿。

  • • template_name · language · output_format
  • • ds / ds01… as JSON strings
  • • return_file_stream for download
閱讀 API 指南
fetch · /api/convert 
const res = await fetch(`${API_BASE}/api/convert`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    template_name: "lesson_m09_sales_order",
    language: "zh-CN",
    output_format: "excel",
    return_file_stream: true,
    return_file_name: true,
    ds: JSON.stringify({
      orderNo: "SO-2026-0412",
      customer: "Northwind",
      lines: [
        { sku: "A-100", qty: 2, price: 120 },
        { sku: "B-220", qty: 1, price: 890 }
      ]
    })
  })
});
const blob = await res.blob();
// download blob as .xlsx

程式畫表 vs JsonXcel

別再為改欄寬發一版工程。

維度 程式畫儲存格 JsonXcel 範本
版式歸屬 開發者在原始碼裡調合併與像素 業務方編輯熟悉的 xlsx
在地化 在 UI 程式碼中分叉或堆字串 替換 Templates/{lang}；API 不變
變更速度 改欄寬也要發版 替換範本即可，無需重建應用
技能要求 表格邏輯埋在 C#／Java 裡 Excel 能力＋JSON 契約
